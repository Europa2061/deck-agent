# 内置玩家工具流程

[English](player-workflows.en.md)

新会话提供四个任务入口。点击后会填入可编辑的提示词，把光标移到末尾并打开 Steam 键盘。你可以直接补充信息，再自行发送。也可以直接用自然语言提需求，或从 Skills 菜单选择对应技能。

| 方向 | 可以这样说 | 内置能力 |
| --- | --- | --- |
| 游戏修复与配置 | “游戏点开始又退回来，帮我查原因”“把画质配置改一下，保留原设置” | 发现 Steam 多游戏库和 SD 卡游戏、读取指定日志、定位配置候选、预览精确替换并备份、恢复原文件 |
| 存档 | “备份这个游戏的存档”“恢复昨天的版本” | Ludusavi 查询、预览、备份列表、单游戏备份恢复；也支持指定文件或目录备份 |
| Mod 与汉化 | “找支持中文的背包扩容 Mod”“安装这个链接里的汉化” | 按需求搜索、读原始说明、下载、检查压缩包、部署预览、备份覆盖文件、登记、停用、启用、卸载 |
| Decky 插件 | “找能传文件的插件”“安装这个仓库的发行版” | 在 GitHub `decky-plugin` Topic 搜索、读发行说明、下载真实插件包、校验清单、转交 Decky 原生确认 |

## 使用方式与实际范围

这四个流程是 Skills 和专用工具的组合，不是固定脚本菜单。模型可以根据实际情况组合工具，也可继续使用 Pi 的文件、命令、其他 Skills、扩展和 MCP。常规工具没有被隐藏或禁用。

- 内置 Skills：`game-care`、`save-care`、`mod-care`、`decky-plugins`。
- 对应工具：`deck_games`、`deck_saves`、`deck_mods`、`deck_plugins`。
- 修改配置、恢复备份及部署/启停 Mod 时，这些专用工具会发起 GUI 确认。备份和操作记录放在 Decky 数据目录的 `deck-agent/player-tools/`。这不是所有原生命令的统一审批或权限沙箱。
- 工具返回本机证据与操作结果，不自动证明游戏能启动、画质变好或帧率提升；需要实际运行或测量验证。

## 存档

优先识别已安装的 Ludusavi；没有时可按任务在插件数据目录下载固定官方 Linux x64 版本 0.31.0，核对固定 SHA-256，并保存官方许可归档。它不随插件 ZIP 分发，也不需要 sudo。

首次运行会写入已发现的 Steam 游戏库位置，默认保留 10 个完整备份和每个完整备份下 5 个差异备份；已有的专用配置不会覆盖。先预览识别结果，数据库未覆盖的游戏可以明确指定存档路径。恢复前会保护当前进度；结果中的 `before.path` 可作为 `backups`、`preview_restore` 和 `restore` 的 `backupPath` 重新选择。备份工具的空结果或部分失败不会报告为成功。

指定路径的文件备份是逐文件恢复，保留备份后新增的文件。完整目录回退需要模型先核对新增文件并保留可恢复副本。当前没有“游戏退出后自动备份”的触发器，也不自动处理 Steam Cloud 冲突或覆盖云端。

## Mod

搜索可使用网页检索或 GitHub，候选需要阅读作者说明并核对版本、加载器、依赖、原生 Linux/Proton 路径。可以安装用户指定名称、链接或本地包，不限预置游戏清单。

内置部署器支持 ZIP/TAR，保留普通执行权限，拒绝越界路径、重复文件及链接。部署前展示新增和覆盖清单，覆盖文件保存原版副本；按文件归属进行停用、启用和卸载。游戏更新或其他程序已改变文件时，自动恢复会停止，交由模型分析差异。

复杂加载器、专用管理器、7z/RAR 或平台授权，可由模型检查现有工具后选择其他方案。网页搜索使用 Bing RSS；访问失败时可换关键词、改用 GitHub 或其他已连接工具。需要登录、购买或验证码的下载不会绕过平台流程。记录本次下载哈希不等于作者认证；有作者校验时才标记来源校验通过。

## Decky 插件

搜索范围为 https://github.com/topics/decky-plugin 。不维护精选目录；Topic 也不保证兼容、经过审核或尚未上架商店。

准备包后，聊天页面/侧栏出现待安装项。点击「继续安装」，在 Decky 原生弹窗确认；取消后可以让模型对同一安装记录重试。来源和版本记录用于核对与后续更新。

`queued` 表示等待前端处理，不等于安装完成。`observedInstalled` 只表示磁盘清单匹配，仍需检查 Decky 加载和插件功能。安装接口为 Decky 内部接口，调用失败会保留重试入口。Deck Agent 自身使用「关于与更新」，避免任务中重载自己。

## 开发入口

`resources/extensions/player-tools.ts` 通过 Pi `--extension` 加载，JSON 参数经 stdin 交给 `backend/player_tools.py`；实际逻辑位于 `backend/workflows/`。参数不拼接为 shell。修改工具使用跨进程写锁，记录原文件、安装归属和未完成状态。

运行 `python3 -m unittest discover -s tests -p test_player_workflows.py -v` 检查文件流程。`test_pi_integration.py` 使用真实 Pi 和本地测试模型验证工具发现、调用、Skill 发现及 GUI 取消。搜索、真实 Ludusavi 和游戏兼容性仍需外部/设备验证，不能只凭 mock 测试宣称完成。
