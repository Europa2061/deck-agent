---
name: save-care
description: 查找、备份、恢复游戏存档，查看历史备份，或在修改配置与安装 Mod 前保护进度。
---

`deck_saves status` 检查 Ludusavi。缺少时，用户已要求进行备份/恢复任务即可用 install 准备工具固定的官方 Linux x64 程序；它只写插件数据目录并校验官方文件，不使用 sudo。不能安装时说明具体原因，可对用户确认的路径使用 path_backup。

按 Steam AppID 用 find 查询数据库名称，或按用户给出的游戏名查询。用 preview_backup 检查命中的文件及未识别项，再 backup；backups 返回可选择的历史版本。每次只明确处理一个游戏。

恢复先 preview_restore，核对游戏、备份编号与目标账号；工具在 GUI 确认后先保护当前存档，再恢复。游戏应先正常退出，Steam Cloud 冲突要保留各份数据并由用户决定，不能只凭修改时间选择“正确”进度。内置工具默认只做本地备份，不自动覆盖云端。

用户指定文件/目录或数据库未覆盖的游戏，可使用 path_backup(paths,label) 和 path_restore(backupId)。支持多种存档组织方式，原生文件/命令工具仍可用于查找；不要把猜测的路径当成已找到。

成功应有实际文件、工具结果及可追溯编号；空扫描或部分失败须明确报告。当前没有自动游戏退出触发器，不能把一次手动备份描述为已开启自动备份。需要外部磁盘、同步或其他特殊方案时，先核对现有工具和权限，再按用户目标扩展。

恢复结果中的 before.path 是恢复前保护副本，应随恢复结果告诉用户。若要回到恢复前的进度，用 preview_restore 和 restore 的 backupPath 指向该目录。恢复后核对目标文件和工具结果，再请用户进游戏确认实际进度。path_restore 为逐文件恢复快照内文件，会保留备份后新增的文件；需要完整目录回退时，先核对并保护新增文件，再决定是否移除。
