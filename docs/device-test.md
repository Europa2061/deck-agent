# Steam Deck 设备测试

[English](device-test.en.md)

使用专用测试目录，例如 `~/DeckAgent/test`。记录插件版本、构建号、SteamOS、Decky、LCD/OLED 和操作时间。浏览器、CEF 自动检查与实体操作分别记录；本清单不是已通过的测试报告。

## 首次安装和更新

- 只有 Decky、没有另装 Pi/Node 时，安装本地 ZIP 后可启动。
- 前后端版本与 Release 一致；设置、供应商、历史和语音模型保留。
- 从真实 GitHub Release 完成发现、HTTPS 下载、SHA-256 校验、Decky 确认和重载；测试取消、重试、错误校验和安装时忙碌保护。
- 缺少校验文件或安装接口不可用时，手动本地 ZIP 安装指引可用。

## 页面与输入

- Steam 主界面和游戏 overlay 的入口、返回 Steam、切换会话可用。
- 实体 A/B、方向键、肩键、触屏、中文软键盘和弹窗关闭后的焦点恢复可用。
- 854×534 / 1280×800 下正文可读，长列表和弹窗可滚动，操作按钮与输入区不被遮挡。
- 流式回复、Markdown、代码复制、长表格、工具结果和消息阅读状态正常。
- 新会话未发送不增加历史，草稿在切换、退出和重新打开后恢复；失败重试不重复建会话。

## 模型与任务

- 真实供应商连接、模型选择、API Key 保存不回显、失败提示不暴露凭据。
- 创建并读回文件、执行命令、停止、任务补充和独立会话并发符合预期。
- 历史恢复不重放旧任务，扩展 confirm/select/input/editor 取消与提交正常。
- 在测试目录验证一个实际 Skill、扩展和 MCP；记录外部依赖，不能承诺任意扩展兼容。

## 语音与恢复

- 模型下载取消、断网、校验失败、换源和空间不足不会误报就绪。
- 内置/外接麦克风检测与断开重连正常；录音结束后只回填原会话草稿，不自动发送。
- 测试中文、英文和混说，记录录音长度、转写时间、内存和游戏帧时间；不把磁盘体积当成内存占用。
- 检查临时录音在完成/取消后清理，以及休眠、唤醒、断网、插件重载后的状态与进程清理。
- 停止和中断不应被描述为回滚；用文件实际内容核对外部操作结果。

## 诊断与反馈

运行随包诊断脚本，核对版本和运行文件；检查日志轮转、调试开关及脱敏。提交 Issue 时附最短复现和必要证据，遮盖密钥、路径、IP 和私人内容。方法见 [调试](debugging.md)。


## 内置玩家流程（0.8.0，2026-11-05）

- 四个 Skills 的格式检查通过；真实 Pi 的本地测试模型验证了工具/Skill 发现、文件工具调用、GUI 取消不改文件，以及确认后部署 Mod。
- 文件流程覆盖配置备份恢复、Mod 启停卸载与归属冲突、安装中断恢复、执行位保留、插件请求重试、HTTP 206 分段与中断续传。
- 浏览器 1280×800 检查四个草稿入口、插件待安装入口、失败重试及交接参数；无横向溢出、框架错误或未处理的异常。854×534 本轮未完成截图验收。
- Steam Deck：发现 17 个 Steam 游戏。使用独立测试目录与新建测试存档，真实 Ludusavi 0.31.0 完成备份、恢复，以及恢复前保护副本的再次恢复；未改动现有游戏存档。
- 官方 Linux 资产 14389479 字节及 legal.zip 均通过固定 SHA-256。因设备直连下载超时，本轮依赖由 Mac 预取后传到测试目录；后续应继续观察设备网络下的自动准备体验。
- 搜索实际请求已返回网页和 `decky-plugin` Topic 候选；复杂 Mod 加载器和每款游戏的画质/启动效果仍需逐项验证，不能从文件操作成功推断游戏兼容。

- 0.8.0 的系统 Python 启动检查未覆盖 Decky 内置 Python 缺少 `xml.etree` 的情况，导致首次安装后后端无法启动；0.8.1 移除该依赖，并增加禁止导入 XML 模块的启动回归。

- 0.8.2 同时处理冻结程序的 `sys.executable`：玩家工具改用系统 Python，子进程清除 PyInstaller 私有库/启动环境，避免再次启动 PluginLoader；增加真实子进程与污染环境回归。
